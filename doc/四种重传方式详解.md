```
else if (ENABLE_BITMAP)    → Bitmap ACK 处理

```

## 2. PSN-PATH 重传

### 2.1 设计原理

PSN-PATH 是一种基于**包序列号 (Packet Sequence Number)** 与**多路径**协同的重传机制。核心思想：

- 每个数据包根据 PSN 映射到不同的物理路径（通过不同 UDP 源端口实现）
- 乱序包在接收端按"同路径有序、跨路径容忍"原则处理
- 丢失包通过 NACK 触发精确重传，放入 `pendingRetrans` 队列

### 2.2 路径映射

```
PSN = seq / packetSize
pathId = (offset + (PSN % K)) % activePathCount
srcPort = basePort + pathId
```

**代码路径**：`psn-path.cc:69-80`

```cpp
uint32_t PsnPath::GetPsnFromSeq(uint32_t seq, uint32_t packetSize) {
    if (packetSize == 0) return 0;
    return seq / packetSize;
}

uint32_t PsnPath::GetPathIdFromPsn(uint32_t psn, uint32_t k, uint32_t o, 
                                    uint32_t activePathCount) {
    if (activePathCount == 0) return 0;
    if (k == 0) return o % activePathCount;
    return (o + (psn % k)) % activePathCount;
}
```

### 2.5 ReceiverCheckSeqPsnPath（PSN-PATH 专用序列检查）

**文件**：`rdma-hw.cc:1354`

```
ReceiverCheckSeqPsnPath(seq, q, size, cnp)
  │
  ├─ psn < expectedPsn → 重复/旧包，返回 5 (HOLD)
  │
  ├─ psn == expectedPsn → 顺序到达
  │    bitmap[psn % BITMAP_SIZE] = 0
  │    ReceiverNextExpectedSeq += size
  │    向前滑动 bitmap，跳过已收到的连续 PSN
  │    返回 1 (ACK)
  │
  ├─ psn >= expectedPsn + BITMAP_SIZE → 窗口溢出
  │    返回 2 (NACK)
  │
  └─ expectedPsn < psn < expectedPsn + BITMAP_SIZE → 乱序
       bitmap[psn % BITMAP_SIZE] = 1
       检查同路径是否有更早的缺失 PSN
         ├─ 有缺失 → 返回 2 (NACK，指定缺失 PSN)
         └─ 无缺失（跨路径乱序）→ 返回 5 (HOLD，接受但不 ACK)
```

关键差异：PSN-PATH 只对**同一路径**上的缺失发送 NACK，跨路径乱序是容忍的。

## 3. GBN 重传

### 3.1 设计原理

Go-Back-N（GBN）是一种简单的回退重传机制，由两个开关配合工作：

- **`ENABLE_RX_OOO_NACK`**：接收端检测到乱序包时，**立即**发送 NACK
- **`ENABLE_TX_NACK_GOBACK`**：发送端收到 NACK 后，将 `snd_nxt` 回退到 NACK 指定的序列号

### 3.2 接收端：乱序检测与 NACK 生成

**文件**：`rdma-hw.cc:1215` `ReceiverCheckSeq()`

```
ReceiverCheckSeq(seq, q, size, cnp)   // 仅在非 Falcon/非 Bitmap 时调用
  │
  ├─ 顺序到达 (seq == expected)
  │    ReceiverNextExpectedSeq += size
  │    返回 1 (ACK) 或 5 (HOLD，等 chunk 边界)
  │
  ├─ seq > expected → 乱序
  │    ├─ IRN + enableRxOooNack 时：
  │    │    if (未到 nackTimer 且 lastNACK == expected) → 返回 4 (HOLD)
  │    │    设置 nackTimer, lastNACK = expected
  │    │    seq = expected  // 关键：将 seq 设置为缺失的 expected
  │    │    cnp = true
  │    │    返回 2 (NACK)
  │    │
  │    ├─ IRN 普通模式：
  │    │    使用 SACK 块记录乱序区间
  │    │    返回 2 (NACK)
  │    │
  │    └─ 非 IRN 模式：
  │         检查 nackTimer 防重复
  │         返回 2 (NACK)
  │
  └─ seq < expected → 重复包
       返回 1 (ACK) 或 2 (IRN recovery)
```

**文件**：`rdma-hw.cc:1130` `ReceiveAck()`

## 4. Bitmap 重传

### 4.1 设计原理

Bitmap 重传使用**独立的 `BitmapRetransModule` 模块**（`bitmap-retrans-module.h`），对每个流维护发送/接收状态：

- **发送端**：维护 `outstanding` 队列（已发送未确认的包）和 `pendingRetransSeqs` 集合（标记待重传的序号）
- **接收端**：维护 `bitmap`（位图，标记窗口内哪些 PSN 已收到）和 `expectedSeq`
- **反馈**：周期性发送 ACK 附带当前 `ackSeq`（累积确认），NACK 触发发送端查询位图找到缺失的序号

### 4.2 模块数据结构

**文件**：`bitmap-retrans-module.h:42-63`

```cpp
struct TxState {
    std::deque<TxSegment> outstanding;          // 已发送未确认的包队列
    std::unordered_set<uint32_t> pendingRetransSeqs;  // 等待重传的序号
};

struct RxState {
    uint32_t expectedSeq{0};                    // 期望的下一个字节序号
    std::vector<uint8_t> bitmap;                // 位图，大小 = m_bitmapSize
};
```

**文件**：`rdma-hw.cc:876` `ReceiveAck()`

```cpp
    uint32_t old_snd_una = qp->snd_una;
    qp->Acknowledge(seq);
```

**关键特性**：

## 5. Falcon 重传

### 5.1 设计原理

Falcon 是一种类似 TCP SACK + 累积确认的重传机制，使用独立的 `FalconRetransModule` 模块（`falcon-retrans-module.h`）：

- **CumAck（累积确认）**：接收端维护 `expectedSeq`，收到顺序包时递增
- **Bitmap（位图）**：接收端用 64-bit bitmap 标记窗口内已收到的乱序 PSN
- **ReoWnd（重排序窗口）**：发送端维护一个时间窗口，超过窗口的乱序才触发重传
- **选择性 ACK**：`OnAck()` 返回 bitmap 中标记已收到但未被 CumAck 覆盖的字节数

### 5.2 模块数据结构

```cpp
        uint32_t startPsn = missingSeq / qp->psnPath.packetSize;

            PsnRetransRequest req;
            req.startPsn = startPsn;
            req.endPsn = startPsn;
            req.epoch = qp->psnPath.mappingEpoch;
            qp->psnPath.pendingRetrans.push_back(req);
        }
    }
}
```

### 5.8 配置参数解析

| 配置项 | NS3 属性 | 默认值 | 说明 |
|-------|---------|--------|------|
| `ENABLE_FALCON` | `EnableFalcon` | false | Falcon 重传开关 |
| `FALCON_REO_WND_NS` | `FalconReoWnd` | 200000 (ns) | 重排序窗口时间 |

**关键特性**：
- Falcon 64-bit bitmap 是**硬编码**在 `qbbHeader` 中的
- 支持**选择性 ACK**：通过 bitmap 告知发送端哪些乱序包已收到（`selectiveAckedBytes`）
- 重排序窗口（ReoWnd）用于区分"乱序但可能还在路上"和"真正丢失"
- Falcon 开启后完全接管收发两端，与 `ReceiverCheckSeq` 互斥
